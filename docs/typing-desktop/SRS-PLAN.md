# FSRS 单词记忆实施说明

评分、调度与自动参数优化都在桌面端 `typing-desktop/core` 中运行。`core/src/fsrs.rs` 逐行移植 py-fsrs 6.3.2 的 `Scheduler`，`core/src/srs.rs` 封装评分与掌握判定，并以 `typing-desktop/fixtures/fsrs-golden.json` 逐条对照 py-fsrs 结果；参数训练使用 fsrs-rs（纯 Rust，无 PyTorch）。同步服务器只保存作答日志，不参与调度。

## 范围与数据起点

- Anki 提供已学习的 Word Atlas 词池（经同步服务器 `/api/vocab` 快照），桌面端独立管理中文提示下的英文拼写记忆。
- 记忆以 `word-atlas:<SourceId>` 唯一标识词条，Anki `note_id` 只关联当前内容与媒体。`SourceId` 缺失或冲突时明确报错，不按词面静默合并。
- 网页版的 `word_reviews` 历史由同步服务器首次启动时导入作答日志（设备 `web`），桌面端同步后按日志重放得到卡片状态。
- “未开始”表示尚未完成正式拼写作答，不代表 Anki 新卡。

## 自动评分

只对独立回忆的首次提交评分，不增加四档评分按钮。按照以下优先级执行：

| 条件 | FSRS 评分 |
| --- | --- |
| 答错，或空输入按 Space 看答案 | `Again`（1） |
| 答对且耗时严格大于 20 秒 | `Hard`（2） |
| 答对且耗时严格小于 6 秒 | `Easy`（4） |
| 答对且耗时在 6–20 秒之间，包含边界 | `Good`（3） |

- 错误优先于耗时；答错即为 `Again`。
- core 复核答案并计算评分，保留大小写、首尾空格和 `/` 分隔可接受答案的现有规则。
- 从题目可作答到首次提交记录耗时，使用单调时钟；不计题目加载、提交和订正耗时。页面隐藏期间暂停计时，草稿保存已累计的有效耗时，恢复草稿不把离线时间加入计时。
- 使用未经整数秒四舍五入的毫秒值比较 `6000` 和 `20000`。耗时缺失、为负或非有限数时拒绝正式提交，避免误判为 `Easy`。
- 自由练习的首次独立作答按同一规则评分，写入历史统计并更新 FSRS，可提前复习未到期词。看答案后的订正和结果页主动错词重练不再次更新记忆或统计。
- 到期后的独立作答可产生新的正式评分，即使该词此前已经在同一轮出现。
- 退出尚未作答的题目不产生 `Again`；已确认保存的作答保留。

## 调度与队列

| 参数 | 默认值 |
| --- | --- |
| `desired_retention` | `0.9` |
| `learning_steps` | 1 分钟、10 分钟 |
| `relearning_steps` | 10 分钟 |
| `enable_fuzzing` | 开启；随机数取自 SHA-256(`attempt_id`)，重放结果可复现 |
| 每轮正式作答数量 | 按当前可练词数决定，队列为空时完成 |
| 每日新词数量 | 当前词池中所有尚未开始的词，不设上限 |
| 每轮自由练习数量 | 全部词池中随机抽取最多 20 个不同词，不足时全部取出 |

以上数值与 6/20 秒阈值是 `srs.rs` 的固定默认值，不再通过 YAML 或 `FSRS_*` 环境变量配置。

学习步骤由评分驱动；新词第一次评为 `Easy` 可直接进入长期复习，不保证每词都走完两个短期步骤。

正式队列优先级：已到期的学习/重学词 → 已到期的长期复习词 → 所有尚未开始的词。每题结束后重新检查到期状态，正式复习不抽取尚未到期的熟词来填满一轮。进度总数随当前可练词数变化。自由练习从整个词池随机抽取最多 20 个词作为本轮题目，每题保存后进入本轮下一词，不自动追加题目；遇到冲突题目跳过后继续剩余词。

没有可练习项目时显示下一次到期时间，可选择自由练习。每次到期后重新出题都有新的作答 ID，订正沿用原题状态，不生成新的正式复习机会。

所有调度时间使用 UTC；页面和按日统计使用 `Asia/Shanghai`。

## 状态与持久化

本地 SQLite 默认位于 `%APPDATA%\com.yleoer.cijian\cijian.db`，结构由 `core/src/store.rs` 定义：

- `word_memory` 保存内部整数卡片 ID、稳定词条标识、Card JSON（与 py-fsrs `to_dict()` 兼容）、状态、稳定性、到期时间、首次/最近复习时间和并发版本号。
- `word_reviews` 保存唯一作答 ID、会话 ID、评分、实际作答时间、耗时、更新前后状态和调度配置版本。
- `practice_items` 保存签发题目时的 `scheduled` / `free` 模式，只在本地使用、不同步。仅 `free` 题允许在到期前提交，但实际作答时间仍须晚于上次复习；客户端传入的模式不会改变权限。
- 逐题在同一 SQLite 事务内保存作答统计、复习日志与卡片新状态；同一作答 ID 重试返回原结果，旧卡片版本的并发提交返回冲突并刷新。
- 同步时把其他设备的作答写入 `word_reviews`，再按 `reviewed_at, attempt_id` 顺序重放受影响词条的完整日志（`core/src/sync.rs`）；在使用相同 FSRS 参数时，多设备得到相同计划。当前参数优化的同步限制见下文待办。
- 会话结束只汇总已经保存的作答，不再次推进 FSRS；待提交作答未确认前不显示全部保存成功。
- FSRS 没有独立的 `New` 状态；未建立正式复习记录的词由应用表示为“未开始”。
- “已掌握”（内部 `mastered`）为 `State.Review` 且 `stability >= 21`；其他已有复习记录的词显示“学习中”。“待复习”独立展示，已掌握的词仍参与到期调度。等级进度和话题以完整牌组为分母，正式/自由练习及待复习仍使用 Anki 已学习词池。

## 接口

本地路由 `GET /api/practice/queue`、`POST /api/practice/attempts` 和 `GET /api/memory/summary` 分别提供动态队列、逐题保存和记忆统计，路径与 JSON 沿用网页版。队列响应不返回 `session_limit`；`summary.new_available` 为全部尚未开始词数，`new_today` 为北京时间当天已引入新词数。正式队列默认每次一道，不限制每轮总数；自由模式默认及最多返回 20 道带作答编号的题，显式 `limit` 可进一步缩小批量。

## 参数优化

`core/src/optimize.rs` 在桌面端后台线程运行：启动时检查一次，此后每天一次；提交答案不执行训练。正式练习和自由练习的首次作答均产生复习日志，订正与结果页立即错词重练不产生。相邻间隔至少 1 天、每词前 64 条事件内的复习才计入优化门槛；短期学习事件仍参与状态重建。

- 首次达到 1,000 条有效间隔复习后训练；按时间留出最后约 20% 的事件验证，同一时间点的数据不会同时进入训练和验证。
- 候选 log loss 必须同时优于默认及现用参数，Brier score 不高于现用参数，才自动启用；保持率固定为 `0.9`。
- 完成一次评估后，按北京时间安排下一个自然月的同一日；新增有效记录默认至少 100 条，否则记录“已跳过”并延至下月。失败一天后重试。
- 启用参数时保留所有已安排到期时间，卡片下一次作答时按完整历史重放并应用新参数；正在作答的题目可跨权重版本提交。
- 应用退出导致未完成的记录在下次启动时标为“任务中断”并重新评估。
- 设置环境变量 `CIJIAN_OPTIMIZATION=0` 关闭自动优化，已启用的参数保留。

`fsrs_optimization_runs` 追加保存评估状态、起止时间、日志快照 ID、各项数量、基线及启用版本、原因和完整 JSON 报告；`fsrs_optimizer_state` 保存启用指针和调度进度，新版本记录进入 `srs_configs`。不自动删除历史。

统计页底部“参数优化记录”可查看积累进度、现用版本、下次评估时间及每次评估的详情：

- `GET /api/memory/optimization`：配置、积累进度、运行状态、当前版本与下次计划。
- `GET /api/memory/optimization/runs?before_id=0&limit=20`：按 ID 倒序分页，返回 `items`、`next_before_id`，每页最多 100 条。
- `GET /api/memory/optimization/runs/<id>`：完整记录，不存在返回 404。

### 待办：多设备参数优化同步

目前只同步作答日志，每台桌面设备独立优化 FSRS 参数，参数版本、优化记录及启用时间不共享。同一份日志用不同参数重放，可能得到不同的稳定性与到期时间；启用参数时保留已有到期时间，也需要统一后续生效规则。因此，现阶段不能无条件保证多设备复习计划一致。

当前离 1,000 条有效间隔复习的优化门槛还远，暂不迁移实现，继续使用现有桌面端优化流程。接近门槛前再处理：由服务端统一每天检查是否需要评估、管理参数版本；桌面端启动时获取最新参数并缓存供离线使用，同时明确新版本的重放与生效规则，使各设备最终得到一致的复习计划。

## 验证

在 `typing-desktop` 目录运行 `cargo test`：`golden.rs` 对照 py-fsrs 基准，`store.rs` 覆盖评分边界、到期、幂等、并发冲突与参数变更重放，`optimize.rs` 覆盖门槛、按月跳过、验证门禁、重启恢复与中断重试。修改评分或调度规则后用 `typing-desktop/scripts/gen_fsrs_fixtures.py` 重新生成基准，详见 [typing-desktop/README.md](../../typing-desktop/README.md)。
