# FSRS 单词记忆实施说明

使用 [py-fsrs](https://github.com/open-spaced-repetition/py-fsrs) 实现后端评分、调度与自动参数优化。固定依赖 `fsrs[optimizer]==6.3.2`，服务镜像安装 CPU 版 PyTorch。

## 范围与数据起点

- Anki 提供已学习的 Word Atlas 词池，网站独立管理中文提示下的英文拼写记忆。
- 正式切换时清空旧练习统计，从新作答重新累计；不设计旧统计迁移、历史回放或旧掌握度兼容。
- 首次启用时移除退役的 `practice_sessions`、`word_attempts`、`word_mastery` 表及其索引，后续不再建表。Anki 词库、媒体、同步记录、访问凭证及新的 FSRS 数据保留；重启不会清理正式复习历史。
- 新记忆以 `word-atlas + SourceId` 唯一标识词条，Anki `note_id` 只关联当前内容与媒体。`SourceId` 缺失或冲突时明确报错，不按词面静默合并。
- “未开始”表示尚未在网站完成正式拼写作答，不代表 Anki 新卡。

## 自动评分

只对独立回忆的首次提交评分，不增加四档评分按钮。按照以下优先级执行：

| 条件 | FSRS 评分 |
| --- | --- |
| 答错，或空输入按 Space 看答案 | `Again`（1） |
| 答对且耗时严格大于 20 秒 | `Hard`（2） |
| 答对且耗时严格小于 6 秒 | `Easy`（4） |
| 答对且耗时在 6–20 秒之间，包含边界 | `Good`（3） |

- 错误优先于耗时；答错即为 `Again`。
- 后端复核答案并计算评分，保留大小写、首尾空格和 `/` 分隔可接受答案的现有规则。
- 从题目可作答到首次提交记录耗时，使用单调时钟；不计题目加载、提交请求和订正耗时。页面隐藏期间暂停计时，草稿保存已累计的有效耗时，恢复草稿不把离线时间加入计时。
- 使用未经整数秒四舍五入的毫秒值比较 `6000` 和 `20000`，并传入 py-fsrs 的 `review_duration`。耗时缺失、为负或非有限数时拒绝正式提交，避免误判为 `Easy`。
- 自由练习的首次独立作答按同一规则评分，写入历史统计并更新 FSRS，可提前复习未到期词。看答案后的订正和结果页主动错词重练不再次更新记忆或统计。
- 到期后的独立作答可产生新的正式评分，即使该词此前已经在同一轮出现。
- 退出尚未作答的题目不产生 `Again`；已确认保存的作答保留。

## 调度与队列

| 参数 | 默认值 |
| --- | --- |
| `desired_retention` | `0.9` |
| `learning_steps` | 1 分钟、10 分钟 |
| `relearning_steps` | 10 分钟 |
| `enable_fuzzing` | 开启；确定性测试关闭 |
| 每轮正式作答数量 | 按当前可练词数决定，队列为空时完成 |
| 每日新词数量 | 当前词池中所有尚未开始的词，不设上限 |
| 每轮自由练习数量 | 全部词池中随机抽取最多 20 个不同词，不足时全部取出 |

学习步骤由评分驱动；新词第一次评为 `Easy` 可直接进入长期复习，不保证每词都走完两个短期步骤。

正式队列优先级：已到期的学习/重学词 → 已到期的长期复习词 → 所有尚未开始的词。每题结束后重新检查到期状态，正式复习不抽取尚未到期的熟词来填满一轮。进度总数随当前可练词数变化。自由练习从整个词池随机抽取最多 20 个词作为本轮题目，每题保存后进入本轮下一词，不自动追加题目；遇到冲突题目跳过后继续剩余词。

没有可练习项目时显示下一次到期时间，可选择自由练习。每次到期后重新出题都有新的作答 ID，订正沿用原题状态，不生成新的正式复习机会。

所有调度时间使用 UTC；页面和按日统计使用 `Asia/Shanghai`。

## 状态与持久化

- 新增 `srs.py` 封装评分、`Scheduler.review_card`、记忆状态转换、回忆概率与掌握判定。
- `word_memory` 保存内部整数卡片 ID、稳定词条标识、状态、学习步骤、稳定性、难度、到期时间、首次/最近复习时间和并发版本号。
- `word_reviews` 保存唯一作答 ID、会话 ID、评分、实际作答时间、耗时、更新前后状态和调度配置版本。
- `practice_items.mode` 持久保存签发题目时的 `scheduled` / `free` 模式；旧表启动时新增该列，旧题默认为 `scheduled`，保留已有题目和历史。仅 `free` 题允许在到期前提交，但实际作答时间仍须晚于上次复习；客户端传入的模式不会改变权限。
- 逐题在同一 SQLite 事务内保存作答统计、复习日志与卡片新状态；同一作答 ID 重试返回原结果，旧卡片版本的并发提交返回冲突并刷新。
- 浏览器持久化未确认提交并顺序重试；草稿恢复先处理待提交事件，确认保存后再移除。保留实际作答时间与接收时间，校验时钟偏移和时间顺序，不能用整轮开始时间或重试时间替代作答时间。
- 会话结束只汇总已经保存的作答，不再次推进 FSRS；待提交作答未确认前不显示全部保存成功。
- py-fsrs 没有独立的 `New` 状态；未建立正式复习记录的词由应用表示为“未开始”。
- “已掌握”沿用参考项目：`State.Review` 且 `stability >= 21`；其他已有复习记录的词显示“学习中”。“待复习”独立展示，已掌握的词仍参与到期调度。

## 接口

已提供 `GET /api/practice/queue`、`POST /api/practice/attempts` 和 `GET /api/memory/summary`，分别提供动态队列、逐题保存和记忆统计。队列响应不再返回 `session_limit`；`summary.new_available` 为全部尚未开始词数，`new_today` 保留为北京时间当天已引入新词数，不再返回 `daily_new` 限额。正式队列默认每次一道，不限制每轮总数；自由模式默认及最多返回 20 道带作答编号的题，显式 `limit` 可进一步缩小批量。两种模式均通过同一作答接口事务保存统计与 FSRS 状态。

## 配置与参数优化

配置位于 backend/config/config.yaml 的 memory 节点。FSRS_DESIRED_RETENTION、FSRS_EASY_SECONDS、FSRS_HARD_SECONDS、FSRS_PARAMETERS_PATH 可通过 .env 或进程环境变量覆盖，Compose 同样传入这些配置。旧 `memory.daily_new` 和 `FSRS_DAILY_NEW` 已停用并忽略，旧配置不会限制新词。默认使用库提供的 21 个权重，不需要先训练。6 秒/20 秒为可配置的评分规则，不由 FSRS 自动学习。

### 自动训练与启用

服务启动后在后台检查一次作答日志，之后默认每 24 小时检查一次，适合每日逐步积累复习记录；没有新增数据时也不提前训练。首次达到 1,000 条有效间隔复习后，在下一次日常检查中自动调用独立 Python 子进程训练，提交答案的接口不执行训练。正式练习和自由练习的首次作答均产生复习日志，订正与结果页立即错词重练不产生。所有复习完整保留，其中相邻间隔至少 24 小时、每词前 64 条事件内的复习才计入优化门槛，与 py-fsrs 6.3.2 的优化器规则一致；短期学习事件仍参与状态重建。

- 按时间留出最后约 20% 的事件验证，同一时间点的数据不会同时进入训练和验证。训练区间要求至少 512 条有效间隔复习，验证要求至少 100 条有效复习，不足时保存跳过原因。
- 在子进程中调用 `Optimizer(review_logs).compute_optimal_parameters()`；限制为 CPU 单线程，默认最长运行 3,600 秒。训练只读截至快照日志 ID 的数据，期间新增作答下次评估使用。
- 比较候选、默认及现用参数。候选 log loss 必须同时优于两组基线，Brier score 不高于现用参数，才自动启用；未改善继续使用现用参数。保持率默认 `0.9`，不自动调整。
- 完成一次评估后，按北京时间安排下一个自然月的同一日，月末自动缩至当月末日；到期后由下一次日常检查触发，正常运行时可能延后不到 24 小时。新增有效记录默认至少 100 条，否则留下“已跳过”记录并延至下月；跳过月份的新增数据继续累计。
- 失败保存异常原因，24 小时后自动重试。SQLite 事务、唯一运行约束和 120 秒可续租租约防止重复训练；中断任务在租约过期后记录中断并重新尝试。
- 启用参数时保留所有已安排到期时间。卡片下次正式复习才根据完整历史重建状态、应用新参数；正在作答的题目可跨权重版本正常提交。评分规则改变仍会拒绝旧题目。
- 数据库保存当前启用指针，重启自动恢复已接受参数；新版本记录进入 `srs_configs`。关闭自动优化后使用手动参数文件或默认权重。

### 配置

`optimization` YAML 节点与以下环境变量对应，Compose 均已转发；环境变量优先。数值必须为正整数。

| 环境变量 | 默认值 | 含义 |
| --- | --- | --- |
| `FSRS_AUTO_OPTIMIZE` | `true` | 后台评估及已接受参数的自动恢复，支持 true/false、1/0 |
| `FSRS_OPTIMIZER_CHECK_SECONDS` | `86400` | 后台检查间隔（秒），默认每天一次 |
| `FSRS_OPTIMIZER_MIN_NEW_REVIEWS` | `100` | 后续评估要求的新增有效间隔复习数 |
| `FSRS_OPTIMIZER_TIMEOUT_SECONDS` | `3600` | 每次训练子进程最长运行秒数 |

### 记录查看与回退

统计页底部展开“参数优化记录”，可查看积累进度、现用版本、下次评估时间，以及每次评估的数据范围、数量、误差、结果和版本。支持刷新与加载更早记录；完整 JSON 包含 21 个候选权重及原用权重。所有查询沿用访问密码保护。

- `GET /api/memory/optimization`：配置、积累进度、运行状态、当前版本与下次计划。进度按后台检查周期更新。
- `GET /api/memory/optimization/runs?before_id=0&limit=20`：按 ID 倒序分页，返回 `items`、`next_before_id`，每页最多 100 条。
- `GET /api/memory/optimization/runs/<id>`：完整记录，不存在返回 404。

`fsrs_optimization_runs` 追加保存评估状态、起止时间、日志快照 ID、总/有效/新增数量、基线及启用版本、原因和完整 JSON 报告；`fsrs_optimizer_state` 保存启用指针和调度进度。不自动删除历史。统计数据库同目录的 `fsrs-optimization/` 保存 `run-N.log`、`run-N.json` 和 `run-N-baseline.json`，应和数据库一起备份。训练失败时进程日志保留，接口与页面可查看错误原因。

从旧配置更新时，如果实际 `.env` 已设置 `FSRS_OPTIMIZER_CHECK_SECONDS=300`，需改为 `86400` 或删除该覆盖项，再重启/重建服务；否则会继续使用显式配置的旧间隔。

回退时设置 `FSRS_AUTO_OPTIMIZE=false`，将 `FSRS_PARAMETERS_PATH` 指向之前已接受的 `run-N.json` 或相应的 `run-N-baseline.json`，然后重启服务；回到库默认权重则清空该路径。历史记录保留，既有到期计划仍在下次复习时应用回退参数。

### 手动离线工具

需要单独分析时仍可使用只读命令（正常运行无需手动触发）：

```powershell
.\.venv\Scripts\python.exe -m pip install "fsrs[optimizer]==6.3.2"
.\.venv\Scripts\python.exe typing-practice/backend/optimize_fsrs.py --db typing-practice/data/stats/stats.db --output typing-practice/data/stats/fsrs-candidate.json
```

当前已有个性化参数时用 `--current <当前文件>` 加入比较。工具只读数据库，不会触发应用初始化或旧数据清理，不覆盖当前参数文件。

该命令采用相同门槛、时间划分与验证规则，只生成独立参数文件，不更新服务的启用指针。`--through-id` 可固定日志快照边界。

## 本地验证

在仓库根目录使用本地虚拟环境运行，无需额外的测试环境配置文件：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s typing-practice/backend -p 'test_*.py'
node --test typing-practice/frontend/src/app.test.cjs typing-practice/frontend/src/stats.test.cjs
```

自动测试覆盖错误评分优先级、5999/6000/20000/20001 毫秒边界、无效耗时、暂停与恢复计时、订正不计分、到期边界、同轮重复到期、幂等重试、并发版本冲突、事务回滚、UTC/上海跨日和 Anki 同步后词条身份稳定性。本地隔离数据库与浏览器还验证了键盘操作、自动切题、草稿恢复和实际服务断连后的提交重试。

自动优化测试覆盖 999→1,000 条门槛、按月跳过与新增累积、验证门禁、保留到期时间、旧题跨权重提交、重启恢复、手动回退、失败重试、并发租约与中断结果隔离、历史分页及访问控制。真实优化器另用模拟历史在本机子进程验证，不将模拟日志混入实际用户数据库。
